# 飞书循环

遵守根 [AGENTS.md](../../../AGENTS.md)，按[工作流程](../workflow.md)处理已绑定 cz-cli 群的反馈。

先按[唤醒与监听](../workflow.md#唤醒与监听)检查实际连接、启动或续建原生 Monitor；保持一个五分钟补扫，交接记录当前实测状态。
每次事件或定时唤醒都运行 `bun scripts/maintenance.ts intake feishu`，读取 pending 的完整话题上下文；新根消息与旧话题回复都要处理，不能只查群根消息。
识别值得处理的缺陷、需求和使用问题，忽略系统通知与自身回写。
先完成可自行查证的调查，再按工作流程判断是否存在需要人工决定的问题。
优先推进已有任务；证据充分的新问题完成认领、修复、验证和独立审查。
审查通过后按工作流程合入 PR；影响产品的改动只发布 nightly，验证产物后回报。
按配置的 Bot 回报策略和[对外回复](../workflow.md#对外回复)回复原话题。
保存任务关联、回复回执或明确处置后逐项 ack，未处理项留在队列；读取不完整时不越过缺口。私有内容不直接转发到 GitHub。
每轮最多推进一个实施任务；完成或遇到真实阻碍时保存交接并结束。等待决定仍读取并回应其他反馈，已满足的暂停条件不另等一次批准。
