# 反思循环

遵守根 [AGENTS.md](../../../AGENTS.md) 和[工作流程](../workflow.md)，每十二小时回看上次已检查位置以来的提交、任务、真实反馈和验证结果；首次查看最近一天。保存覆盖范围和下次读取位置。

只整理三类有证据的内容：
- [易误解点](../understanding.md)：已经导致错误判断的项目设计或产品边界，写清误解、事实和依据。
- [待决事项](../decisions.md)：今日仍需人工干预的产品定位、设计或授权问题，给出事实、一个具体决定、推荐方案和受影响任务；从原讨论核对是否已经回答。
- [重复故障](../recurring-failures.md)：反复失败的链路、已验证原因、恢复方法及下次应检查什么；原因不明就如实记录。

合并相同事项，关闭已解决的待决；未经确认的判断不能成为产品规则。私有事实留本机记录，公开文档只保留可公开的依据。
不按天复制日志，不全面补写设计文档，不为保持活跃制造重构；无新发现保存检查位置后结束，不改文档或发消息。
需要人工决定时更新本机当日待决清单，由反馈 Agent 在相关原讨论提出具体问题；不自动群发日报，不重复催问。
发现可验证的代码或维护故障，关联已有任务或登记给反馈 Agent，不另做一套实施队列，也不接管正在进行的任务。
文档改动从 `policySha` 开独占 worktree，验证和独立审查后保留提交并在本机记录待切换；不推送 main、不发版，由反馈 Agent 在无进行中实施时按 workflow 切换控制版本。每轮最多一个文档整理任务。
