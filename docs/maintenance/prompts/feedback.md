# 反馈循环

遵守根 [AGENTS.md](../../../AGENTS.md) 和[工作流程](../workflow.md)，统一处理 GitHub Issue、PR、评论及绑定飞书群的新话题和回复。

启动和每次唤醒核对唯一飞书 Monitor；保留一个五分钟原生补扫，同时检查两个来源，安静或任务受阻不延长间隔。
每次唤醒读取 runtime `control/daily-decisions.md`；未提问且有原讨论的事项按原渠道规则提一次具体问题并记回执，已回答的更新任务。没有原讨论的保留集中清单，不群发或重复催问。
事件到达先读取对应原讨论及最新回复，查稳定来源和已有任务；不为一条消息先等待所有历史话题扫描。
定时补扫运行 `bun scripts/maintenance.ts intake github` 和 `intake feishu`；耗时扫描在后台执行，读取已有 pending，不并发启动同一来源的扫描。未完成或失败不算检查成功。
优先阅读新反馈和后续决定，关联跨渠道的同一问题；忽略系统通知与自身回写。相关任务先查[易误解点](../understanding.md)、[待决事项](../decisions.md)和[重复故障](../recurring-failures.md)。
使用问题直接回应；明确需求自主调查、修复和验证。真正缺少产品决定时保存事实、推荐方案和影响，仅暂停依赖该决定的实施。
长实施使用原生后台子 Agent，给按 workflow 从精确基线自建的 worktree（不用 Agent 自带的 worktree 隔离参数）、验收条件，不同步等待其完成；主会话在安全边界继续读取和回应反馈，先对账进行中的实施者。
不同任务可并行，分别认领、使用独占 worktree 并保存执行者；同一任务只保留一个实施执行者，不因定时唤醒重复派工。共享资源操作按已有锁与回执协调，受阻任务不阻塞其他反馈。
每次唤醒检查 runtime `control/policy-pending.md` 中已审查的待切换提交；按 workflow 协调所有受影响执行者到安全交接边界后切换 `policySha`，不能安全切换则保留记录下轮再查。
完成后派新的独立审查 Agent，只给最终 diff、SHA、验收条件、验证日志和规则入口；源码变化重新审查。
按现有守卫推送、创建 PR、核对 CI 并合入；需要发版时只发布 nightly，验证产物后回报。
在原讨论自然交流，私有飞书内容不直接转发 GitHub。保存任务关联、处置或发送回执后逐项 ack，未处理项保留；不把读取当完成，不因一个任务受阻漏掉其他反馈。
本轮实施完成或遇到真实阻碍时保存交接；监听和补扫继续工作。已满足的条件式暂停不再等一次批准。
